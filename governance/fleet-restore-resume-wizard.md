Resuming a Claude Code session that is hours old / large via `--continue` no longer drops straight into the conversation: it parks on an interactive menu — "1. Resume from summary (recommended) / 2. Resume full session as-is" — with a warning that full resume consumes a substantial share of usage limits. Four consequences for any fleet restore:

1. **The relaunch script does not complete the restore.** Every session comes up frozen on the menu. Any free-form text sent to it lands on the highlighted menu default, not in the conversation. Clear each wizard with a bare Return (`cc-butler-compact--send-return`) — but only after confirming BY BUFFER CONTENT that the menu is actually present (some small sessions resume with no wizard at all), and verify a sample by screen afterwards rather than trusting the sweep's return value. Note `cc-butler-compact--send-return` takes a DIRECTORY, not a session name: passing a name does not error, it falls through to the current directory and presses Return in the caller's own terminal while returning `t` as if it worked. Always a full path.

2. **Restore-with-memory has a price: roughly one full context re-read per session.** Option 1 (summary) immediately runs a /compact over the whole prior context. For a 14-session fleet that is millions of input tokens. Surface this cost to 정수님 before choosing full restore vs. fresh-plus-rehydrate, especially under budget pressure.

3. **Therefore expect a WAVE OF COMPACTIONS after the sweep — that is the answer landing, not an anomaly.** Answering option 1 *is* the compaction, so minutes later a batch of sessions will show `/compact` in progress, drop to 0k, and fire "waiting for your input" notifications together. Sessions far below the 300k threshold will be among them, because the threshold was never involved. Do not read this as a rogue process, do not hunt it, and do not escalate it as an unexplained leak. The tell that it is benign: the compacting set is exactly the set that was parked on a wizard. Cross-check that list before spending anything.

4. **The resumed session comes back on its PARKED model, not the saved default** — `/model` saves only a default for new sessions. See [[butler-model-switch-lands-after-compaction]] for the fix and its timing (switch at CTX≈0 right after compaction settles; verify by statusline, never by the `/model` echo).

**Why:** 2026-08-11 post-reboot restore established 1, 2 and 4. The canary (monocle-iros) surfaced the wizard and the model stranding; 13 relaunched sessions all parked on menus while butler and steward were both about to type into them — one stray submit-Enter could have selected "resume full session" repeatedly, the exact budget accident the summary option exists to avoid. The guarded sweep cleared 12; one (16-scheduler, 51k) had no wizard.

Consequence 3 was added after 2026-08-12, when it cost real work: the butler answered six parked sessions with option 1 and described them afterwards as "answered", which read as inert. The steward then found six sessions compacting at once — several at 114k–154k, well under threshold — could not attribute it, and spent a verification pass plus an escalation on a phantom rogue process. **The rule that would have prevented it was already written here in §2 and neither role recalled it.** The failure was recall, not a missing principle, which is why this is a revision rather than a new note: the fact was recorded as a *cost* warning, so nobody matched it against an *observation*. A principle that only states a price will not fire when what you are holding is a symptom.

**How to apply:** On any fleet restore: (1) canary one session first (`broadcast-verify-one-first`) and make sure the canary is representative of the axis that varies — size, not merely age, arms this wizard, so a small canary proves nothing about a large session; (2) present the memory-vs-cost choice to 정수님 with the per-session re-read cost stated; (3) after mass relaunch, run the guarded wizard sweep before ANYONE sends text to a worker; (4) **write down which sessions you answered, and hand that list to whoever watches the fleet** — that list is what makes the incoming compaction wave attributable instead of alarming; (5) after compactions settle, run the model sweep per [[butler-model-switch-lands-after-compaction]]; (6) treat statusline CTX/MODEL figures as lagging claims — re-read at the moment of use. The cheap tell for a still-parked session is that it reports NO MODEL in `list_claude_sessions` and `?` context in `session_status`.
